## Active Work

The provider-neutral acquisition boundary now supports an ordered provider chain plus bounded bulk concurrency. Settings persists one or more enabled providers in priority order; bulk Staging and Sync Library runs process up to three missing tracks side by side, with each track retaining its own provider hierarchy, retries, staging path, and progress. Refrain searches the highest-priority provider first, falls through when it cannot produce an automatic-quality match or its bounded automatic acquisition attempts fail, and stops once a provider successfully stages the selected recording. Retryable provider/transport exhaustion triggers a fresh automatic rerun of the complete ordered chain, up to three total chain attempts with backoff, before the job is finally surfaced as `Failed`. Persisted jobs left in `searching` or `downloading` after an app restart are treated as interrupted because provider runtime state is process-local; startup converts them into retryable failed rows instead of leaving them stuck forever. The manual desktop Sync Library action now explicitly starts a fresh acquisition session: previous acquisition rows, candidate/error state, and Refrain-owned staging artifacts are abandoned before Local sync, and Monochrome's temporary playback cooldown is cleared so the new session gets a fresh first-provider attempt. Monochrome remains the default first provider; Antra and Sockseek can be enabled and ordered after it or ahead of it. Manual resolution is reserved for identity ambiguity: if Refrain already identified an automatic-quality candidate and the transfer fails across the provider chain, the job remains a retryable acquisition failure instead of asking the user to choose the same known match manually. If no provider identifies an automatic match, Staging preserves every returned candidate, groups candidates by provider in provider-priority order, and carries provider provenance through Add/Reject actions so identical provider tokens cannot collide. Compatible exact-ISRC duplicates no longer force manual review solely because multiple equivalent provider records exist, and retryable failure of one exact release now tries the next ranked compatible exact release from the same provider before provider fallback. Retry and Search Again refresh unresolved `Needs Resolution` rows through the current provider chain; Sync Library discards those prior rows and searches from scratch. Interrupted Monochrome downloads resume from their `.part` file with HTTP range requests; request-start failures, transient HTTP responses, interrupted bodies, invalid transient payloads, and empty responses use bounded exponential retries. If the primary `tracks.monochrome.st` download path still fails, including 403, transport, or non-FLAC protocol failures, Monochrome resolves a compatible legacy lossless candidate for the same recording and tries that path before the coordinator advances to the next configured provider. Legacy playback now prefers `LOSSLESS` direct-FLAC manifests and explicitly skips segmented MPEG-DASH responses instead of mis-parsing them as JSON. Monochrome search preserves numeric sample-rate and bit-depth metadata when the provider exposes it, while legacy `LOSSLESS` candidates are represented as 44.1 kHz / 16-bit. A confirmed playback outage opens a short Monochrome cooldown so the remaining bulk queue falls through to the next configured provider instead of repeating the same broken playback path for every track. Antra signs in through a browser-approved device code, discovers authenticated mirror endpoints, checks exact ISRC before text fallback, and currently exposes Tidal/Qobuz FLAC candidates with one in-process Antra download at a time. Sockseek candidates retain reported bitrate, sample rate, bit depth, format, and size, while equal-confidence results prefer FLAC and then other lossless formats. Successful downloads from every provider are inspected before the downloaded state is persisted so candidate format, size, bitrate, sample rate, and bit depth reflect the actual staged audio. Milestone 14 automatically hands successful provider output into verification/import, with selective processing retained for recovery rows outside the explicit fresh-session reset. Live end-to-end one-click FLAC acquisition/import smoke tests have passed with Monochrome and Antra. Milestone 15 is complete: Sync Library keeps the approved Local-then-Spotify two-scope workflow, serializes canonical library mutation, publishes live phase/progress events, persists source deltas and final reconciliation/acquisition counts, records partial outcomes and aggregated warnings, and exposes recent sync history in Settings.

Active work is Milestone 17: manifest-based Library Mirroring to another mounted filesystem, including target persistence, incremental verified copies, resolved playlist output, and ownership-safe cleanup of only Refrain-managed mirror paths.

## Known Issues

Port `43817` must be available while starting Spotify authorization. Refrain reports an authentication error rather than choosing a different port when it is occupied.

Unsigned or ad-hoc-signed release packages may require platform security confirmation. Production signing/notarization depends on release credentials being available.

The older public Monochrome API pool is unhealthy from the development Mac as of 2026-09-28: `api.monochrome.tf` and several mirrors fail DNS or connection, while the reachable Samidy mirror reports an upstream Tidal token-refresh failure. Current Monochrome source instead routes normal search/download traffic through `tracks.monochrome.st`; Refrain mirrors that contract and the primary live FLAC acquisition/import path has been smoke-tested successfully.

Sockseek/Soulseek remains implemented but is not the active acquisition path. Independent Sockseek and `soulseek-cli` tests both reached the Soulseek server and then failed during login, so further Sockseek changes are deferred until the network/upstream condition can be isolated.
